## Hipótesis y límite

Las particiones privadas generadas CoDSP `p1` y `p8` contienen 7.936 y 6.134 llamadas `f2d(` estáticas respectivamente, **no son conteos de llamadas por frame**. Convertir todos los valores binary80 usa redondeo, ramas y especializaciones para NaN y denormales. El caso frecuente cuando una operación de binary64 se almacena como x87 tiene exponente double normal, bit explícito J=1 y once bits bajos del significando a cero; su retorno a binary64 puede construirse directamente como bits exactos, evitando redondeo. Ningún cambio se aplica a subnormales, números no canónicos, infinitos, NaN, representaciones inexactas o conversiones de 32/64 bits: usan la rutina original. Se preservan todos los bits, incluido signo, carga NaN y cero.

Se añadió `CODRECOMP_X87_NORMAL_F2D` a `tools/recomp/recomp_rt.h`, con macro definido **después** de la función original. El CMake Android aplica el flag solo a CoDSP `p1/p8`, y el comando optativo es:

```
python tools/recomp/build_android.py --hot-x87-transform --x87-normal-f2d --jobs 3
```

No se modificaron los archivos privados de código generado, las partidas, los shaders ni los gráficos. Sin `--x87-normal-f2d` el compilador usa exclusivamente `f2d` original. El build inicial recompila muchas particiones porque se tocó una cabecera común; futuras pruebas deben priorizar limitar dependencias para acelerar iteraciones.
